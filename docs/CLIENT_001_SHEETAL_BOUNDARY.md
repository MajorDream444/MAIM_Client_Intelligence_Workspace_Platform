# Client #001: Sheetal Boundary

Status: planning boundary

Sheetal / Shakti is the likely first client workspace.

This document protects the distinction between the reusable platform and the first client instance.

## Client #001 Purpose

Use Sheetal as the first proof case for the Client Intelligence Workspace Platform.

The goal is not to rebuild the Shakti Portal as a one-off.

The goal is to discover which workspace patterns are reusable across future clients while preserving Sheetal's doctrine, voice, and journey.

## What Can Become Reusable

- client dashboard model
- journey timeline
- deliverables library
- knowledge vault structure
- reports area
- AI coach interaction pattern
- client configuration schema
- source-of-truth map
- review and approval gates

## What Must Stay Client-Specific

- Shakti doctrine
- sacred language
- practitioner voice
- program names
- rituals
- client-specific assets
- client-specific deliverables
- private notes
- unpublished source materials

## Required Standard

Before any Sheetal workspace implementation, create a client workspace specification that answers:

- What is the client mission?
- What does the client see?
- What does Major operate?
- What does AI assist?
- What data is created?
- What requires human approval?
- What is reusable for Client #002?
- What must never be generalized?
